# 联合优化为什么没有超过独立预测头

本轮不新增网络模块。目标是查清检测和预测互相拉动的原因，修正评估与匹配，并在同一套 TransFusion-LC 初始化上比较几种交互方式。mini 只看机制和收敛趋势，下面的数字不是论文结论。

更强的检测参照仍是同一份融合权重、未经 mini 微调的 TransFusion-L：mAP 0.5486，NDS 0.5719。本轮所有联合模型仍从 1 epoch mini LC（mAP 0.5300，NDS 0.5080）初始化，这样和已有的 B、C 可比。没有把 L 换成新的训练起点，也没有解冻 LiDAR backbone。

## 代码问题

` .gitignore ` 里原来的 `data` 会忽略任意名为 `data` 的目录，`infrauni/data/future_tracks.py` 因此没有进入 Git。规则改为只忽略仓库根目录的 `/data/`。该文件和本轮的匹配、评估改动已推到 `main`（`620c30b`）。未来轨迹仍由 `tools/build_future_tracks.py` 生成，缓存不入库。

预测评估原先先丢掉 6 s 不完整的真值，再做当前检测匹配。一个当前框是对的、但轨迹在 6 s 前结束的目标，会被算成假阳性。现协议先对全部当前真值做类别内匈牙利匹配（2 m），匹配到短轨迹的预测记为忽略，不记假阳性。minADE、minFDE、MR 和 EPA 的分母只用 6 s 终点有效的真值。假阳性只统计没有匹配到任何当前框的预测。总指标是动态类的类别平均，不把 barrier 和 traffic_cone 算进预测均值；这两类仍保留逐类数字。检测继续用 nuScenes 官方 mAP、NDS。

每个 refinement block 原先会按修正后的框重新匹配。DeTra 自己的 `joint_loss` 也是每轮重匹配。验证集上，已训好的 C1、C2、C3 若按修正框重匹配，Query 切换率只有 0.8% 到 1.2%。这不是 mAP 下降的主因，但同一个 Query 的框和未来轨迹不该中途换目标。现在的监督只在 TransFusion 提案上匹配一次，后面的 block 共用这次分配。切换率仍按“如果重匹配会怎样”记录，不参与梯度。

DeTra 的 `object_logits` 没有替换 TransFusion 的类别和分数。对照用的融合是 `fused = transf_score * (0.5 + sigmoid(object_logit))`：存在概率约 0.5 时分数不变，概率为 0 时降到一半，为 1 时升到 1.5 倍。主表仍用 TransFusion 分数。

预测损失不再直接把当前中心当作可学习的轨迹原点。`detach_anchor` 时未来点写成“偏移 + 断开的原点”，偏移仍可训练。`box_mode=none` 时导出框保持 TransFusion 框，轨迹相对这个框重锚。`causal_time` 只挡住 t=0 去读 t>0，未来 Query 仍可读当前 Query。这是前向截断，和 C3 那种“反传后恢复非轨迹参数梯度”不是同一件事。因果 mask 写在本地 MC-DeTra 的 `RefinementBlock` 里，默认关闭；补丁在 `patches/detra_causal_time.diff`。`third_party` 仍不入库。

Laplace NLL 没有恢复。上一轮它在 C1 第 2 个 epoch 把框打成非有限值，匈牙利匹配直接失败。本轮官方检测头在更长的解冻训练里也会出现非有限输出，训练现在会跳过这一步，而不是把非有限值写进参数。

## 框修正和梯度

C1 的检测器是冻结的，提案框 mAP 仍是 0.5300。修正后的框 mAP 是 0.5004。下降来自框本身，不是分数。相对提案，C1 的平均修正是平面位移 0.189 m、高度 0.065 m、对数尺寸 0.302、朝向 0.085 rad。和轨迹真值比，中心误差从 0.243 m 增到 0.343 m。

官方误差项对得上：car 的平移误差从 0.177 增到 0.285，pedestrian 从 0.129 增到 0.274。car 的尺度误差 0.239 到 0.234，朝向 0.171 到 0.175，几乎没变。motorcycle 的尺度误差从 0.411 增到 0.581。mAP、NDS 下降的主要几何原因是中心被挪走，不是朝向。

C2 的提案 mAP 已经降到 0.5257，修正后再降到 0.4887，中心误差同样从 0.242 m 增到 0.343 m，平面位移 0.222 m。C3 关掉预测对共享权重的反传后，平面位移只有 0.040 m，中心误差 0.240 m 到 0.240 m，修正框 mAP 0.5265，和提案 0.5260 一致。对数尺寸在 C3 里仍然平均变化 0.280，但没有把 mAP 打下去。

`_decode` 在送进 DeTra 之前断开了 TransFusion 框的梯度。预测损失因此到不了 `prediction_heads`。它能移动的是 DeTra `box_head` 加在提案上的残差，以及通过 Query 特征到达的 `decoder.1`、`query_proj` 和 `bev_proj`。

在训好的 C2 上取 4 个训练帧，把检测损失和预测损失的梯度做余弦。整段参数的余弦接近 0，符号随帧变化：`box_head` 约 0.02，`time_attn` 约 -0.03，`decoder.1` 约 -0.04，`query_proj` 约 -0.07，`bev_proj` 约 0.17。这不是一步里很大的反向冲突。伤害是多步累积的：预测损失把当前中心当成轨迹原点，中心就朝未来轨迹靠，官方平移误差变大。断开原点后，同一批帧上 `decoder.1` 的余弦变成轻微正值，但 4 帧不够当成稳定的梯度手术结论。

分数融合没有造成 C1、C2 的 mAP 下跌。C1 融合后 0.5017，相对 0.5004；C2 是 0.4927 相对 0.4887；C3 是 0.5318 相对 0.5265。增益只有千分位，主结果继续用 TransFusion 分数。

D1 的检测在 15 个 epoch 里始终是 0.5300 / 0.5080，因为导出框就是 TransFusion 框。预测在第 2 个 epoch 还不如 B，主要是行人：pedestrian minADE 2.464，而 B 是 1.487，car 已经是 0.534，和 B 的 0.568 接近。第 5 个 epoch 行人降到 0.967，总 minADE 0.731。第 15 个 epoch 行人 0.866，car 0.519，总 minADE 0.671，EPA 0.313。按验证 minADE 选择第 15 个 epoch。检测没有变好，也没有变差。

D5 在第 2 个 epoch 的中心误差是 0.240 m 到 0.241 m，平面位移 0.028 m。断开原点之后，预测损失没有再把框拉开。mAP 0.5259，接近提案 0.5260，低于原 LC 的 0.5300，和 C3 那种解冻后的轻微漂移同类。预测还没起来：minADE 1.553。继续往第 3 个 epoch 训时，解冻的官方检测头出现非有限输出，匈牙利匹配报错，这一跑停在第 2 个 epoch。

F0 训到第 5 个 epoch 时权重仍全部有限。修正框 mAP 0.5243，NDS 0.5116；提案 NDS 0.5136。mAP 比 LC 低 0.006，NDS 高 0.004。中心误差 0.242 m 到 0.254 m，平面位移 0.067 m，比 C2 的 0.222 m 小。预测是目前最好的一档：minADE 0.650，minFDE 1.076，MR 0.123，EPA 0.349。car 0.503，pedestrian 0.833。第 6 个 epoch 里官方检测头先出现非有限输出，随后图像 Query decoder 的权重变成非有限。第 6 到第 15 个 epoch 的 checkpoint 含有 NaN，不能当结果。从那一步起后面的 step 也因为显存分配失败被跳过，没有再产生有效更新。D1 的 10、15 epoch 指标是训练结束后单独评估的；训练进程还占着显存时，验证子进程会在 spconv 里分配失败。

匀速基线的 pedestrian minADE 是 1.174，好于 2 epoch 的 B（1.487），差于 D1 第 15 epoch（0.866）和 F0 第 5 epoch（0.833）。car 上匀速是 0.966，独立头和 DeTra 都更好。

## 结论

双向联合优化失败，是因为未来轨迹把 DeTra 修正后的当前中心当成了原点。预测损失沿这个几何捷径挪框，官方平移误差大约变成两倍，mAP 从 0.530 降到 0.500 或 0.489。Query 切换率只有约 1%，分数融合也只改变千分位，都不是这个下跌的原因。共享权重上的梯度余弦在单步里接近正交，不能代替中心误差和 mAP 的测量。

预测信息没有在这份 mini 上提高检测。能保住检测的条件是：不要让预测损失移动当前中心。D1 把框固定住，15 epoch 后预测超过 2 epoch 的独立头，检测仍是 0.5300。只断开反传、仍允许未来 Query 从前面影响当前 Query 的 C3，检测也接近原 LC，但预测变差。F0 反过来关掉这条前向，预测在第 5 epoch 最好，检测 mAP 略降、NDS 略升，还不能说未来运动改善了当前检测。

DeTra 在 2 epoch 时不如独立头，是因为行人还没收敛，再加上框被拽走。把框固定之后，第 5 epoch 开始超过独立头。差距主要在训练长度和原点是否可被预测损失移动，不是还缺一个新模块。

## 还没做完的部分

D5 没有第 5、10、15 epoch 的有效 checkpoint。从第 2 个 epoch 续训时，官方检测头在第 3 个 epoch 初就给出非有限输出；跳过该 step 之后，下一步在注意力 softmax 上分配显存失败，进程退出。F0 的有效结果停在第 5 个 epoch，原因同上，而且第 6 个 epoch 的权重已经非有限。因此不能把 D5、F0 说成已经训到 15 epoch。D2 的“只改中心”没有单独重训。Refinement block 仍是 2 个，没有先加到 DeTra 论文里的 3 个。BEV 仍是插值多尺度，轨迹仍是相对位移回归。Laplace 没有打开。没有接 RESOLVE 或 V2X-Seq。

下一步最值得做的是保住 F0 第 5 epoch 这种小残差，同时不让解冻的图像 decoder 在第 6 个 epoch 变成非有限。可以先降低解冻模块的学习率，或在 `optimizer.step` 前丢掉非有限梯度。D1 已经说明：原点固定时，DeTra 预测可以在不改变检测的前提下超过 2 epoch 的独立头，但要给行人 5 个 epoch 以上。在检测 mAP 还没有高于 0.530 之前，不把增加层数或换损失当成修复。ForeSight 的可取之处是未来 Query 提供检测先验，而不是把当前框坐标当成轨迹原点；本轮的 D5、F0 只借用了这个划分，没有实现它的记忆队列。
